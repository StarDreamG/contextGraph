# Design Principles

## 1. Stable Context and Dynamic Tracking Must Be Separated
Product background belongs in docs/product.
Task status belongs in Issues and Projects.
Code implementation belongs in PRs and commits.

## 2. Every Requirement Must Be Verifiable
A requirement is not ready until it has acceptance criteria.

## 3. Codex Should Execute, Not Invent Product Direction
Codex may suggest product improvements, but should not silently expand the product scope.

## 4. Small Deliverable Units
Prefer small Issues and small PRs.

## 5. Traceability
Every code change should be traceable back to a requirement, bug, or design decision.
